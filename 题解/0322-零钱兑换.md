# 322. 零钱兑换

> [!abstract] 一句话本质
> **用无限个给定面额凑出 amount，求最少硬币数**，不是看某个硬币能不能用，而是枚举最后一枚硬币。

> [!quote] 链接
> - https://leetcode.cn/problems/coin-change/

## 题目

给定硬币面额数组 `coins` 和总金额 `amount`，每种硬币数量无限，求凑成总金额所需的最少硬币个数。凑不出则返回 `-1`。

## 思路（从暴力到最优）

最直接的想法是枚举每一步选哪枚硬币。要凑出金额 `i`，如果最后一枚硬币是 `coin`，那么前面必须刚好凑出 `i - coin`。

这些子问题会重复出现，所以用动态规划记录每个金额的最优答案。

定义：

```text
dp[i] = 刚好凑成金额 i 所需要的最少硬币个数
```

初始化：

```text
dp[0] = 0
其他 dp[i] = amount + 1
```

`amount + 1` 是一个不可能的答案，因为凑出 `amount` 最多也只会用 `amount` 枚 `1` 元硬币；如果没有 `1` 元硬币，只会更不可能。因此它可以作为“不可达”的哨兵值。相比 `INT_MAX`，它还能避免 `dp[i - coin] + 1` 溢出。

转移时枚举最后一枚硬币：

```text
dp[i] = min(dp[i], dp[i - coin] + 1)
```

其中 `+1` 表示新加入的最后一枚硬币 `coin`。由于最优方案的最后一枚硬币一定来自 `coins`，枚举所有 `coin <= i` 就能覆盖全部可能。

如果某个金额凑不出来，它的 `dp[i]` 会一直保持 `amount + 1`。即使参与后续转移，`amount + 1 + 1` 也不会让答案变得更优，所以最后仍可用哨兵值判断是否不可达。

## 关键卡点

> [!warning] 我当时卡在这
> - `amount + 1` 是“不可能答案”，用来表示不可达；不要用 `INT_MAX`，否则 `+1` 有溢出风险。
> - `dp[i]` 必须理解成“刚好凑成金额 i”的最少硬币数。
> - 转移是在枚举最后一枚硬币：先凑出 `i - coin`，再补上一枚 `coin`。
> - 这题和 279. 完全平方数本质一样：都是求最少个数；区别是本题的可选面额来自 `coins`，279 的可选面额是 `1, 4, 9, 16...`。

## 代码

```cpp
class Solution {
public:
    int coinChange(vector<int>& coins, int amount) {
        vector<int> dp(amount + 1, amount + 1);
        dp[0] = 0;

        for (int i = 1; i <= amount; i++) {
            for (const int coin : coins) {
                if (coin <= i) {
                    dp[i] = min(dp[i], dp[i - coin] + 1);
                }
            }
        }

        return dp[amount] == amount + 1 ? -1 : dp[amount];
    }
};
```

## 复杂度

- 时间：`O(amount * coins.size())`
- 空间：`O(amount)`
