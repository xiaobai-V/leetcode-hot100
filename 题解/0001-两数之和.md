# 1. 两数之和

> [!abstract] 一句话本质
> **边遍历边查补数**，不是双重循环暴力枚举，而是用哈希表把"查找另一个数"从 O(n) 降到 O(1)。

> [!quote] 链接
> - https://leetcode.cn/problems/two-sum/

## 题目
给定整数数组 nums 和目标值 target，找出和为 target 的两个整数的下标。恰好一个答案，不能重复使用同一元素。

## 思路（从暴力到最优）
1. **暴力**：双重循环枚举所有数对，O(n²)。
2. **哈希优化**：遍历时，对每个 nums[i]，查 target - nums[i] 是否已经在哈希表中。在就直接返回，不在就把当前数存入哈希表继续。
3. **关键细节**：必须先查后插。如果先插入再查，当 nums[i] 恰好等于 target 的一半时（如 {3,3}, target=6），会找到刚插入的自己，返回 [i,i] 错误结果。

## 关键卡点
> [!warning] 我当时卡在这
> - C++ STL 语法不熟练（unordered_map 的 find / 插入方式）
> - 先查后插的顺序问题：反过来会导致同元素匹配自身

## 代码
```cpp
class Solution {
public:
    vector<int> twoSum(vector<int>& nums, int target) {
        unordered_map<int, int> umap;
        for (int i = 0; i < nums.size(); i++) {
            if (umap.find(target - nums[i]) != umap.end()) {
                return {i, umap[target - nums[i]]};
            }
            umap[nums[i]] = i;
        }
        return {-1, -1};
    }
};
```

## 复杂度
- 时间：O(n) 平均，遍历一次，每次哈希查找 O(1)
- 空间：O(n)，哈希表最多存 n 个元素

> [!note] 面试追问点
> 哈希查找平均 O(1)，理论最坏 O(n)（大量哈希冲突退化为链表遍历）。实际中可视为 O(1)。
